# 計算モデル

## 距離の定義

キー中心間のユークリッド距離を積み上げます。単位は u（1u = キーピッチ = 19.05mm）。

左手・右手それぞれについて、その手が打つキーだけを順に並べ、隣り合う打鍵の間の
距離を合計します。**手をまたぐ移動は距離に数えません**（両手は独立に動くため）。

例（ロウスタッガード、QWERTY 刻印の物理位置）

| 遷移 | dx | dy | 距離 |
|---|---|---|---|
| Q → W | +1.000 | 0 | 1.0000 u |
| Q → E | +2.000 | 0 | 2.0000 u |
| Q → S | +1.250 | −1.000 | 1.6008 u |
| S → E | +0.750 | +1.000 | 1.2500 u |

## アクションと打鍵数

**アクション数** … 打鍵動作の回数。同時に押すキーは何個でも 1。

**打鍵数** … 押されたキーの延べ数。同時押しはキーの数だけ数える。

| 配列定義 | アクション | 打鍵 |
|---|---|---|
| `"あ": "a"` | 1 | 1 |
| `"さ": "space+u"` | 1 | 2 |
| `"ゔ": "space+f+a"` | 1 | 3 |
| `"じゃ": ["space+i", "y"]` | 2 | 3 |

`+` でつないだものは何キーでも 1 アクション、配列（`[ ]`）は要素数ぶんの
アクションになります。ローマ字入力は 1 文字 = 1 キー = 1 アクションです。

**同時率**（打鍵数 ÷ アクション数）は、同時打鍵への依存度を表します。
ローマ字入力は常に 1.00 です。

## 同時打鍵の扱い

同じ手で複数キーを同時に押す場合、キーの間を順に移動したとはみなさず、
**キー中心の重心**をそのアクションにおける手の代表位置とします。

物理的には複数の指が並行して動くため、移動距離を単純合計すると過大評価に
なります。また、同時打鍵には本来「どちらを先に押すか」がないので、
順番を仮定すると記述順によって結果が変わってしまいます。重心を使えば
どちらの問題も生じません。

左右の手にまたがる同時打鍵は、各手が独立に自分のキーへ移動するだけです。

## 親指

親指は 4 指とは別の経路として集計します。手のひらは動かさず、親指だけが
独立に動くためです。指の経路に混ぜると、「中段 → スペース → 中段」の往復が
打鍵のたびに加算されて実態から乖離します。

左右それぞれの合計値（`left_total_u` / `right_total_u`）と総距離には
親指を含みます。

## 打ち方の選択

同じかなに複数の打ち方が定義されている配列では、どれを選ぶかで結果が変わります。
`--segment-policy` で切り替えます。

| 方針 | 選び方 | ジオメトリ依存 |
|---|---|---|
| `min_distance`（既定） | 移動距離が最小になる打ち方 | あり |
| `min_actions` | アクション数が最小になる打ち方 | なし |
| `longest` | 最長一致（先頭から最も長いかな列を優先） | なし |

`min_distance` は動的計画法で、「そのとき指がどこにあるか」まで考慮して
経路全体が最短になる打ち方を選びます。熟練者が無意識に近い方を選ぶ挙動に
近い一方、ジオメトリによって打鍵数が変わる可能性があります。
打鍵数を配列固有の値として示したい場合は `min_actions` を使ってください。

拗音や外来音を分解して打つ配列では、この選択は発生しません。
「ゃ」にキーを割り当てておけば「しゃ」は自動的に 2 打鍵に分解されます。

## ジオメトリ

| ID | 内容 |
|---|---|
| `row_staggered` | ANSI 標準。上段 +1.5u / 中段 +1.75u / 下段 +2.25u |
| `ortholinear` | 完全格子。段のずれなし |
| `column_staggered` | 分割型の一例。列ごとの縦オフセットは調整可能 |

`column_staggered` の列オフセット（小指 0 / 薬指 0.25 / 中指 0.5 / 人差し指 0.25）は
暫定値です。実機に合わせる場合は `typing_distance.py` の `COLUMN_STAGGERED` を
書き換えてください。

## 記号の扱い

### お題文の前処理

`texts/wagahai.txt` は、青空文庫版『吾輩は猫である』冒頭をひらがなに開いたうえで、
次の読み替えを行っています。

| 元 | 読み替え後 | 回数 | 理由 |
|---|---|---|---|
| `―` | `ー` | 6 | ダッシュを長音記号に寄せた |

読み替えはこの1件だけです。`・`（8回）と `？`（1回）は原文のまま残しており、
各配列が自分でどう入力するかを定義します。

## 未定義文字の扱い

**お題文に未定義の文字が1つでもある配列は、計算そのものを行いません。**

読み飛ばして続行すると、その文字ぶんの打鍵数・アクション数・距離がすべて 0 に
なります。仮にある配列だけ 100 文字を入力できなかった場合、その 100 文字を
「打たずに済ませた」ことになり、その配列だけが不当に有利な数値になります。
比較を目的とする以上、これは黙って通してよい誤差ではありません。

かな配列・ローマ字配列とも同じ扱いです。未定義文字があれば `ValueError` になり、
`run.py` はその配列を結果から除外して理由を表示します。

配列を作っている途中で試算したい場合に限り、`--allow-unmapped`
（API では `allow_unmapped=True`）で読み飛ばせます。その場合は警告が出ます。

### かな → ローマ字（ローマ字入力配列のみ）

| かな | ローマ字 |
|---|---|
| `ー` | `-` |
| `、` | `,` |
| `。` | `.` |
| `・` | `/` |

`・` は MS-IME・Google 日本語入力の既定に従い、`/` キーで入力するものとしています。

### 記号 → 物理キー

英字 30 キーに収まらない文字は、配列ごとに物理キーを指定しています。

| 文字 | QWERTY | Dvorak |
|---|---|---|
| `ー`（→ `-`） | `-` | `'` |
| `、`（→ `,`） | `,` | `w` |
| `。`（→ `.`） | `.` | `e` |
| `・`（→ `/`） | `/` | `[` |
| `「` | `[` | `-` |
| `」` | `]` | `=` |
| `！` | `rshift` + `1` | `rshift` + `1` |
| `？` | `lshift` + `/` | `lshift` + `[` |

シフトは打鍵する手と逆の手で押す前提です（`1` は左手なので右シフト、
`/` は右手なので左シフト）。

Dvorak での `「」` は、その配列で `[` `]` を出す物理キー（数字段の `-` `=`）に
割り当てています。IME の実装によっては物理キー基準になる可能性があり、
この部分は環境依存です。

かな配列では、記号も配列作者が定義するため、エンジン側の読み替えは介在しません。

## ローマ字テーブル

訓令式を基本とし、打鍵数が少なくなる綴りを採用しています。

- `し` = `si`、`つ` = `tu`、`ふ` = `hu`、`じ` = `zi`
- `っ` は次の子音を重ねる（`かった` → `katta`）
- `ん` は母音・な行・や行・語末の前だけ `nn`、それ以外は `n` 一打
  （`てんき` → `tenki`、`ほんや` → `honnya`、`にほん` → `nihonn`）

ヘボン式（`shi` / `tsu` / `fu`）では打鍵数が増えます。比較に影響するため、
どちらを採るかは明示が必要です。

## 既知の制約

**連続シフトを考慮していません。** 同じシフトキーを押しっぱなしにする打ち方でも、
アクションごとにシフトを 1 打として数えるため、打鍵数が実態より多く出ます。
アクション数と距離は正しい値です。スペース同時打鍵を多用する配列では
影響が大きくなります。

**変換・確定操作を含みません。** かな入力後のスペース（変換）や Enter（確定）は
数えていません。ローマ字入力とかな配列の双方にかかる負荷なので、比較の観点では
除外しても大きな歪みは生じないと考えていますが、絶対値としては過小です。

**時間軸を持ちません。** 同時打鍵は「同時に押した」という事実だけを扱い、
押下・解放のタイミングは考慮しません。そのため同時打鍵の速度的な利点は
この指標では表現できません。**距離はエネルギー効率の指標であって、
速度の指標ではありません。**

**指の使い分けを固定しています。** 手の割り当ては標準的なタッチタイプ
（左手 = `qwert` `asdfg` `zxcvb`、右手 = 残り）に従います。実際の運指が
異なる場合は `HAND_OF_KEY` を調整してください。
