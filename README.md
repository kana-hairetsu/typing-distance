# typing-distance

日本語キーボード配列の**打鍵単純移動距離**を算出するツールです。

お題文を打ち込んだときに指がどれだけ動くかを、キーボードの形状（ロウスタッガード／
オーソリニア／カラムスタッガード）ごとに計算します。かな直接入力（新配列）と
ローマ字入力の両方に対応しています。

## 何がわかるか

『吾輩は猫である』冒頭 10,872 字を打った場合（ロウスタッガード）

| 配列 | 打鍵数 | アクション数 | 総移動距離 |
|---|---|---|---|
| 薙刀式 | 15,238 | 10,682 | 18,896 u（360 m） |
| QWERTY ローマ字 | 19,111 | 19,110 | 35,542 u（677 m） |
| Dvorak ローマ字 | 19,111 | 19,110 | 33,891 u（646 m） |

1u はキーピッチ 19.05mm です。左右の手ごとの内訳、親指の移動距離、
1打鍵あたり・1アクションあたりの平均も出せます。

**この数値は「疲れにくさ」の目安であって、速度の指標ではありません。**
詳しくは [docs/methodology.md](docs/methodology.md) をご覧ください。

## 使い方

### 必要なもの

Python 3.8 以降。Excel を読み書きするツールだけ openpyxl が必要です。

```
pip install openpyxl
```

### 計算する

```
python run.py
```

`layouts/` にある全配列 × 全ジオメトリを計算し、`results/` に CSV を出力します。

```
python run.py --text texts/wagahai.txt      # お題文を指定
python run.py --layout naginata             # 配列を絞る
python run.py --segment-policy min_actions  # 打ち方の選び方を変える
```

### 配列を追加する

かな配列（新配列）の場合、Excel で入力するのが確実です。

1. `layouts/_template_input.xlsx` をコピーして、配列名を付ける
2. 「単打」シートに配列名と、シフトなしで打つかなを記入
3. 同時打鍵があれば「2キー同時」「3キー同時」「4キー同時」の各シートへ。
   シフトキーを指定してから、そのキーと同時に押したときのかなを記入します
4. 「個別指定」シートに自動で反映されます（青字）。文字キー同士の同時打鍵や
   順次打鍵は、ここに直接入力してください
5. 「単打」シート右上の集計で、重複や未反映がないか確認
6. JSON に変換

```
python tools/xlsx_to_json.py layouts/あなたの配列.xlsx layouts/あなたの配列.json
python run.py
```

ローマ字系配列（英字30キーの並び替え）は Excel 不要です。
`typing_distance.py` の `alpha_layout()` を1行足すだけで追加できます。

```python
OONISHI = alpha_layout("大西配列", "上段10文字", "中段10文字", "下段10文字",
                       extra={"-": "-"})   # 「ー」の物理キー
```

## 議論したいこと

計算モデルにはいくつも判断が入っています。異論のある箇所は Issue でご指摘ください。
特に次の点は、まだ「これが正しい」と言い切れないと考えています。

- 同手の同時打鍵を、キー中心の重心で扱ってよいか
- 親指の移動を指と分けて集計してよいか
- 同じかなに複数の打ち方がある場合、距離最小の経路を選ぶのが妥当か
- 連続シフト（シフトを押しっぱなしにする打ち方）を考慮していない点
